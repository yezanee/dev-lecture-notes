# 섹션 5: 동적 프록시 기술

---

## 핵심 아이디어

프록시를 직접 100개 만드는 대신, **런타임에 자동으로 생성**하자!

"이 로직(로그 찍기)을 실행해줘"라는 **공통 처리기 1개**만 만들면, 어떤 인터페이스든 프록시를 자동 생성해줌.

## 리플렉션

정적인 메서드 호출(`target.callA()`)을 메타정보(`Method`)로 추상화하여 공통 로직을 만들 수 있음.

**주의**: 런타임에 동작하므로 컴파일 시점에 오류를 잡을 수 없음. 실수가 런타임에서야 터짐. 일반적으로 사용 비권장.

## JDK 동적 프록시

- **인터페이스 필수**
- `InvocationHandler` 인터페이스 구현 → 공통 로직 작성
- `Proxy.newProxyInstance()`로 프록시 생성

```java
// 핵심: InvocationHandler 하나로 모든 프록시의 공통 로직 처리
public class TimeInvocationHandler implements InvocationHandler {
    private final Object target;

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        long startTime = System.currentTimeMillis();
        Object result = method.invoke(target, args); // 실제 호출
        long endTime = System.currentTimeMillis();
        log.info("TimeProxy 종료 resultTime={}", endTime - startTime);
        return result;
    }
}
```

> **비유**: "모든 전화는 비서가 먼저 받아서 통화 기록을 남기고 연결해드립니다." 비서 1명이 모든 전화를 처리.

## CGLIB (Code Generator Library)

- **구체 클래스만으로 동적 프록시 생성 가능** (인터페이스 불필요)
- `MethodInterceptor` 인터페이스 구현
- `Enhancer`를 사용하여 프록시 생성 (구체 클래스를 상속)

```java
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(ConcreteService.class);
enhancer.setCallback(new TimeMethodInterceptor(target));
Object proxy = enhancer.create();
```

**CGLIB 제약**: 기본 생성자 필요, final 클래스/메서드 불가

## JDK 동적 프록시 vs CGLIB

| 구분 | JDK 동적 프록시 | CGLIB |
|------|----------------|-------|
| 기반 | 인터페이스 구현(implement) | 구체 클래스 상속(extends) |
| 필수 조건 | 인터페이스 | 기본 생성자 |
| 핸들러 | InvocationHandler | MethodInterceptor |
| 제약 | - | final 클래스/메서드 불가 |
