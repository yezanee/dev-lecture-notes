# 섹션 7: 빈 후처리기 (BeanPostProcessor)

---

## 개념

스프링 빈 저장소에 등록하기 직전에 객체를 조작하거나 **완전히 다른 객체로 바꿔치기**할 수 있는 메커니즘.

> **비유**: 공항 보안 검색대. 승객(빈)이 탑승구(스프링 컨테이너)에 가기 전에 검색대(후처리기)를 거침. 여기서 짐을 확인하고, 필요하면 **사람을 바꿔치기**(원본 → 프록시 교체)할 수도 있음!

## 빈 등록 과정

```
객체 생성 → [빈 후처리기] → 스프링 빈 등록
                ↓
        원본을 프록시로 교체 가능!
```

1. 객체 생성
2. 빈 후처리기에 전달
3. 조작/변환 (원본 → 프록시로 교체 가능)
4. 스프링 빈으로 등록

## BeanPostProcessor 인터페이스

```java
public interface BeanPostProcessor {
    Object postProcessBeforeInitialization(Object bean, String beanName); // 초기화 전
    Object postProcessAfterInitialization(Object bean, String beanName); // 초기화 후
}
```

## 왜 이게 강력한가?

- 모든 빈이 등록 직전에 후처리기를 거침
- 여기서 **"이 빈에 프록시를 씌울까?"를 자동으로 판단**하고 교체 가능
- 컴포넌트 스캔으로 등록되는 빈에도 적용 가능!

## 자동 프록시 생성기 (AnnotationAwareAspectJAutoProxyCreator)

스프링 부트가 자동 등록하는 특별한 빈 후처리기. 등록된 Advisor들을 자동으로 감지하여 필요한 곳에만 프록시를 자동 생성.

이름이 길지만 하는 일은 단순:
1. 등록된 Advisor들의 포인트컷을 확인
2. 새로 등록되는 빈이 포인트컷에 해당하면 → 프록시로 교체
3. 해당 안 하면 → 그냥 원본 등록

> **비유**: 경비원이 "VIP 명단(포인트컷)"을 들고 서서, 명단에 있는 사람(빈)만 리무진(프록시)에 태워보냄.

## 포인트컷의 이중 역할

1. **생성 단계**: 프록시 적용 대상인지 판단 ("이 빈에 프록시를 씌울까?")
2. **사용 단계**: 어드바이스를 적용할 메서드인지 판단 ("이 메서드 호출에 어드바이스를 적용할까?")
