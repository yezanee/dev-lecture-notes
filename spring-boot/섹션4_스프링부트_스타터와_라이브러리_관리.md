# 섹션 4: 스프링 부트 스타터와 라이브러리 관리

## 1. 라이브러리 관리의 어려움

프로젝트를 시작할 때 개발자가 직접 겪는 고통:

1. **라이브러리 선택**: 수많은 라이브러리 중 어떤 것을 선택해야 하는가?
2. **버전 선택**: 선택한 라이브러리의 어떤 버전을 써야 하는가?
3. **호환성 문제**: 각 라이브러리의 버전들끼리 호환이 되는가?

> 프로젝트 초기 세팅에 상당한 시간이 소비되었다.

스프링 부트는 이 문제를 두 가지 기능으로 해결한다:
- **외부 라이브러리 버전 관리**
- **스프링 부트 스타터 제공**

## 2. 라이브러리 직접 관리 (스프링 부트 없이)

`io.spring.dependency-management` 플러그인을 **사용하지 않으면** 모든 라이브러리의 버전을 직접 지정해야 한다:

```groovy
plugins {
    id 'org.springframework.boot' version '3.0.2'
    // id 'io.spring.dependency-management' version '1.1.0'  ← 사용 안 함
    id 'java'
}

dependencies {
    // 스프링 웹 MVC
    implementation 'org.springframework:spring-webmvc:6.0.4'
    // 내장 톰캣
    implementation 'org.apache.tomcat.embed:tomcat-embed-core:10.1.5'
    // JSON 처리
    implementation 'com.fasterxml.jackson.core:jackson-databind:2.14.1'
    // 스프링 부트 관련
    implementation 'org.springframework.boot:spring-boot:3.0.2'
    implementation 'org.springframework.boot:spring-boot-autoconfigure:3.0.2'
    // LOG 관련
    implementation 'ch.qos.logback:logback-classic:1.4.5'
    implementation 'org.apache.logging.log4j:log4j-to-slf4j:2.19.0'
    implementation 'org.slf4j:jul-to-slf4j:2.0.6'
    // YML 관련
    implementation 'org.yaml:snakeyaml:1.33'
}
```

**문제점:**
- 웹 프로젝트 하나를 하려면 수많은 라이브러리를 알아야 한다
- 각 라이브러리의 버전을 하나하나 골라야 한다
- **각 라이브러리 버전의 호환성**을 직접 확인해야 한다

## 3. 스프링 부트 라이브러리 버전 관리

### 핵심: io.spring.dependency-management 플러그인

```groovy
plugins {
    id 'org.springframework.boot' version '3.0.2'
    id 'io.spring.dependency-management' version '1.1.0'  // ← 핵심!
    id 'java'
}

dependencies {
    // 버전을 명시하지 않아도 된다!
    implementation 'org.springframework:spring-webmvc'
    implementation 'org.apache.tomcat.embed:tomcat-embed-core'
    implementation 'com.fasterxml.jackson.core:jackson-databind'
    implementation 'org.springframework.boot:spring-boot'
    implementation 'org.springframework.boot:spring-boot-autoconfigure'
    implementation 'ch.qos.logback:logback-classic'
    implementation 'org.apache.logging.log4j:log4j-to-slf4j'
    implementation 'org.slf4j:jul-to-slf4j'
    implementation 'org.yaml:snakeyaml'
}
```

### 동작 원리: BOM (Bill of Materials)

`io.spring.dependency-management` 플러그인은 `spring-boot-dependencies`에 있는 **BOM 정보**를 참고한다.

- BOM = **자재 명세서** — 제품을 구성하는 모든 부품들에 대한 목록
- 스프링 부트의 `build.gradle` 내 `bom` 블록에 각 라이브러리의 버전이 명시되어 있음
- 현재 프로젝트의 스프링 부트 버전(`version '3.0.2'`)에 맞는 라이브러리 버전이 **자동으로 선택**됨

**확인 방법:**
- [스프링 부트가 관리하는 외부 라이브러리 버전 목록](https://docs.spring.io/spring-boot/docs/current/reference/html/dependency-versions.html)
- [BOM 소스 코드](https://github.com/spring-projects/spring-boot/blob/main/spring-boot-project/spring-boot-dependencies/build.gradle)

### 주의: 스프링 부트가 관리하지 않는 라이브러리

스프링 부트가 모든 라이브러리를 관리하는 것은 아니다. **관리하지 않는 라이브러리는 버전을 직접 명시**해야 한다.

### 라이브러리 버전 변경

스프링 부트가 관리하는 라이브러리의 버전을 변경하고 싶다면:

```groovy
ext['tomcat.version'] = '10.1.4'
```

각 라이브러리의 property 이름은 [공식 문서](https://docs.spring.io/spring-boot/docs/current/reference/html/dependency-versions.html#appendix.dependency-versions.properties)에서 확인할 수 있다.

## 4. 스프링 부트 스타터

### 스타터란?

프로젝트를 시작하는 데 필요한 **관련 라이브러리를 모아둔 세트**이다.

```groovy
dependencies {
    // 이 하나의 의존성으로 위에서 직접 넣었던 모든 라이브러리가 포함된다!
    implementation 'org.springframework.boot:spring-boot-starter-web'
}
```

`spring-boot-starter-web` 하나에 포함되는 것들:
- Spring MVC (`spring-webmvc`)
- 내장 톰캣 (`tomcat-embed-core`)
- JSON 처리 (`jackson-databind`)
- 로깅 (`logback`, `slf4j`)
- 기타 스프링 부트 핵심 라이브러리

> **스타터도 다른 스타터를 사용**할 수 있다 (의존성이 중첩됨).

### 주요 스타터 목록

| 스타터 | 용도 |
|-------|------|
| `spring-boot-starter-web` | 웹 애플리케이션 (MVC, 내장 톰캣) |
| `spring-boot-starter-data-jpa` | JPA 데이터 접근 |
| `spring-boot-starter-validation` | 빈 검증 |
| `spring-boot-starter-actuator` | 모니터링/관리 기능 |
| `spring-boot-starter-test` | 테스트 |
| `spring-boot-starter-security` | 보안 |

### 스타터 이름 패턴

- **공식 스타터**: `spring-boot-starter-*`
  - 예: `spring-boot-starter-web`, `spring-boot-starter-data-jpa`
- **비공식(서드파티) 스타터**: `thirdpartyproject-spring-boot-starter`
  - 예: `mybatis-spring-boot-starter`

> 모든 스타터 목록은 [Spring Initializr](https://start.spring.io/)에서 확인하거나 [공식 문서](https://docs.spring.io/spring-boot/docs/current/reference/html/using.html#using.build-systems.starters)를 참고하면 된다.

## 정리

스프링 부트의 라이브러리 관리 전략:

```
1. 스프링 부트 스타터 → 어떤 라이브러리를 써야 할지 고민 해결
2. io.spring.dependency-management → 라이브러리 버전/호환성 고민 해결
3. 개발자는 스프링 부트 버전만 관리하면 나머지는 자동!
```

스프링 부트가 각 라이브러리의 호환성을 **이미 테스트**했기 때문에, 개발자는 안심하고 사용할 수 있다.
