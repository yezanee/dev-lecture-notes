# 섹션 5: 자동 구성 (Auto Configuration)

## 1. 스프링 부트의 자동 구성이란?

스프링 부트는 **자동 구성(Auto Configuration)** 기능을 통해, 일반적으로 자주 사용하는 수많은 빈들을 **자동으로 등록**해준다.

예를 들어 JPA를 사용한다면:
- `DataSource` 빈
- `JdbcTemplate` 빈
- `TransactionManager` 빈

이런 것들을 개발자가 직접 등록하지 않아도, 스프링 부트가 자동으로 빈을 만들어 등록해준다.

### 자동 구성의 위치

`spring-boot-starter` 의존성 안에 `spring-boot-autoconfigure` 라이브러리가 포함되어 있고, 이 안에 수많은 자동 구성 클래스들이 들어있다.

### 용어 정리: 자동 설정 vs 자동 구성

| 용어 | 의미 |
|------|------|
| **자동 설정** | 넓은 의미 — 빈들을 자동으로 등록해 스프링이 동작하는 환경을 설정 |
| **자동 구성** | 좁은 의미 — 실행에 필요한 컴포넌트 조각을 자동으로 배치 |

강의에서는 주로 "자동 구성"이라는 용어를 사용하며, 문맥에 따라 "자동 설정"도 사용한다.

## 2. 자동 구성 예시 — JdbcTemplateAutoConfiguration

```java
@AutoConfiguration(after = DataSourceAutoConfiguration.class)
@ConditionalOnClass({ DataSource.class, JdbcTemplate.class })
@ConditionalOnSingleCandidate(DataSource.class)
@EnableConfigurationProperties(JdbcProperties.class)
@Import({ DatabaseInitializationDependencyConfigurer.class, 
          JdbcTemplateConfiguration.class,
          NamedParameterJdbcTemplateConfiguration.class })
public class JdbcTemplateAutoConfiguration {
}
```

각 어노테이션의 역할:

### @AutoConfiguration
- 자동 구성을 사용하려면 반드시 이 어노테이션이 필요
- 내부에 `@Configuration`이 있어 빈을 등록하는 자바 설정 파일로 동작
- `after = DataSourceAutoConfiguration.class` → **실행 순서 지정** (JdbcTemplate은 DataSource가 필요하므로 DataSource 자동 구성 이후에 실행)

### @ConditionalOnClass
```java
@ConditionalOnClass({ DataSource.class, JdbcTemplate.class })
```
- **해당 클래스가 클래스패스에 있는 경우에만** 자동 구성이 동작
- 클래스가 없으면 설정 전체가 무효화되고 빈도 등록되지 않음
- **IF문과 유사한 기능**

### @ConditionalOnMissingBean
```java
@Configuration(proxyBeanMethods = false)
@ConditionalOnMissingBean(JdbcOperations.class)
class JdbcTemplateConfiguration {

    @Bean
    @Primary
    JdbcTemplate jdbcTemplate(DataSource dataSource, JdbcProperties properties) {
        JdbcTemplate jdbcTemplate = new JdbcTemplate(dataSource);
        // 설정 적용...
        return jdbcTemplate;
    }
}
```
- `JdbcOperations` 빈이 **없을 때만** 동작 (`JdbcTemplate`의 부모 인터페이스가 `JdbcOperations`)
- 이 기능이 없으면 개발자가 등록한 JdbcTemplate과 자동 구성이 등록한 JdbcTemplate이 **중복 등록**되는 문제 발생
- **핵심: 개발자가 직접 빈을 등록하면 자동 구성은 동작하지 않는다!**

### 주요 자동 등록 설정

| 자동 구성 클래스 | 등록하는 빈 |
|----------------|-----------|
| `JdbcTemplateAutoConfiguration` | `JdbcTemplate` |
| `DataSourceAutoConfiguration` | `DataSource` |
| `DataSourceTransactionManagerAutoConfiguration` | `TransactionManager` |

## 3. @Conditional — 조건부 설정

자동 구성의 핵심 메커니즘. **특정 조건에 맞을 때만** 설정이 동작하도록 한다.

### Condition 인터페이스

```java
@FunctionalInterface
public interface Condition {
    boolean matches(ConditionContext context, AnnotatedTypeMetadata metadata);
}
```

- `matches()`가 `true` 반환 → 조건 만족, 설정 동작
- `matches()`가 `false` 반환 → 설정 무효화
- `ConditionContext`: 스프링 컨테이너, 환경 정보 등
- `AnnotatedTypeMetadata`: 어노테이션 메타 정보

### @ConditionalOnXxx 시리즈

스프링 부트는 개발자가 편리하게 사용할 수 있도록 다양한 `@ConditionalOnXxx`를 제공한다:

| 어노테이션 | 조건 |
|-----------|------|
| `@ConditionalOnClass` / `@ConditionalOnMissingClass` | 클래스가 있는/없는 경우 |
| `@ConditionalOnBean` / `@ConditionalOnMissingBean` | 빈이 등록되어 있는/없는 경우 |
| `@ConditionalOnProperty` | 환경 정보(프로퍼티)가 있는 경우 |
| `@ConditionalOnResource` | 리소스가 있는 경우 |
| `@ConditionalOnWebApplication` / `@ConditionalOnNotWebApplication` | 웹 애플리케이션인/아닌 경우 |
| `@ConditionalOnExpression` | SpEL 표현식에 만족하는 경우 |

**예시: @ConditionalOnProperty**
```java
@ConditionalOnProperty(name = "memory", havingValue = "on")
```
→ 환경 변수 `memory`의 값이 `"on"`일 때만 동작

> `@Conditional`은 **스프링 프레임워크**의 기술이고, `@ConditionalOnXxx`는 이를 확장한 **스프링 부트**의 기술이다.

## 4. 자동 구성의 동작 원리

### 자동 구성 대상 지정

자동 구성을 적용하려면 다음 파일에 자동 구성 대상을 지정해야 한다:

```
resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
```

이 파일에 자동 구성 클래스의 전체 경로를 기재한다.

### 동작 흐름

```
@SpringBootApplication
    ↓
@EnableAutoConfiguration
    ↓
@Import(AutoConfigurationImportSelector.class)
    ↓
AutoConfigurationImportSelector (ImportSelector 구현체)
    ↓
AutoConfiguration.imports 파일을 읽어 자동 구성 클래스를 동적으로 선택
```

### ImportSelector — 동적 설정 로딩

`@Import`에 설정 정보를 추가하는 2가지 방법:

**1. 정적인 방법:**
```java
@Configuration
@Import({AConfig.class, BConfig.class})  // 코드에 대상이 딱 박혀있음
public class AppConfig {}
```

**2. 동적인 방법 (자동 구성이 사용하는 방식):**
```java
public interface ImportSelector {
    String[] selectImports(AnnotationMetadata importingClassMetadata);
}
```
→ 코드로 프로그래밍해서 설정 대상을 **동적으로 선택** 가능

### @SpringBootApplication 내부 구조

```java
@SpringBootConfiguration
@EnableAutoConfiguration  // ← 자동 구성의 핵심
@ComponentScan(excludeFilters = { 
    @Filter(type = FilterType.CUSTOM, classes = TypeExcludeFilter.class),
    @Filter(type = FilterType.CUSTOM, classes = AutoConfigurationExcludeFilter.class) 
})
public @interface SpringBootApplication {}
```

```java
@AutoConfigurationPackage
@Import(AutoConfigurationImportSelector.class)  // ← ImportSelector 구현체
public @interface EnableAutoConfiguration {}
```

**AutoConfigurationExcludeFilter**: 컴포넌트 스캔에서 `@AutoConfiguration`을 **제외**하는 필터. 자동 구성은 컴포넌트 스캔이 아닌 별도의 메커니즘으로 등록되어야 하기 때문이다.

## 5. 자동 구성 — 주의사항

### 자동 구성 내부에서 컴포넌트 스캔을 사용하면 안 된다

- `@AutoConfiguration`과 일반 `@Configuration`은 **라이프사이클이 다르다**
- 자동 구성은 컴포넌트 스캔의 대상이 되면 안 된다
- 자동 구성 내부에서 `@Import`는 사용 가능

### 자동 구성을 언제 사용하는가?

- **라이브러리를 만들어서 제공할 때** 주로 사용
- 일반적인 애플리케이션 개발에서는 컴포넌트 스캔이나 직접 빈 등록을 사용
- 실제로 다양한 외부 라이브러리들이 자동 구성을 함께 제공함

### 자동 구성을 알아야 하는 진짜 이유

> 개발을 진행하다 보면 사용하는 특정 빈들이 **어떻게 등록된 것인지** 확인이 필요할 때가 있다. 이때 스프링 부트의 자동 구성 코드를 읽을 수 있어야 한다. 그래야 문제가 발생했을 때 대처가 가능하다.

자동 구성을 직접 만들 일은 거의 없지만, 자동 구성 코드를 **읽고 이해하는 능력**은 실무에서 반드시 필요하다.
