# 섹션 7: 외부설정과 프로필 2

## 1. 외부 설정 사용 방법 3가지

스프링이 제공하는 외부 설정 조회 방법은 점점 편리해지는 순서로 3가지가 있다:

| 방법 | 편의성 | 타입 안전성 |
|------|--------|-----------|
| `Environment` | 낮음 | 없음 |
| `@Value` | 중간 | 부분적 |
| `@ConfigurationProperties` | **높음** | **완전** |

## 2. Environment 방식

스프링 `Environment`의 `getProperty(key)`를 통해 값을 꺼내 사용:

```java
@Component
@RequiredArgsConstructor
public class MyDataSourceEnvConfig {
    private final Environment env;

    @Bean
    public MyDataSource myDataSource() {
        String url = env.getProperty("my.datasource.url");
        String username = env.getProperty("my.datasource.username");
        // ...
        return new MyDataSource(url, username, ...);
    }
}
```

**단점:**
- `Environment`를 직접 주입받아야 함
- `env.getProperty(key)`를 통해 값을 꺼내는 과정을 **반복**해야 함
- 타입 변환을 직접 처리해야 할 수 있음

## 3. @Value 방식

`@Value`를 사용하면 외부 설정값을 **편리하게 주입**받을 수 있다:

```java
@Slf4j
@Configuration
public class MyDataSourceValueConfig {

    @Value("${my.datasource.url}")
    private String url;
    
    @Value("${my.datasource.username}")
    private String username;
    
    @Value("${my.datasource.password}")
    private String password;
    
    @Value("${my.datasource.etc.max-connection}")
    private int maxConnection;  // 타입 변환 자동!
    
    @Value("${my.datasource.etc.timeout}")
    private Duration timeout;   // Duration 변환도 지원!
    
    @Value("${my.datasource.etc.options}")
    private List<String> options;

    @Bean
    public MyDataSource myDataSource1() {
        return new MyDataSource(url, username, password, maxConnection, timeout, options);
    }
}
```

**주요 특징:**
- `${}`를 사용해서 외부 설정의 키 값을 지정
- **필드**에도 사용 가능, **파라미터**에도 사용 가능
- **타입 컨버팅** 자동 지원 (String → int, Duration, List 등)
- 키를 찾지 못할 경우 **기본값 설정 가능**: `@Value("${my.datasource.etc.max-connection:1}")`

**단점:**
- 하나하나 외부 설정 키를 입력하고 주입받아야 하는 부분이 **번거로움**
- 설정 정보가 늘어나면 관리가 어려워짐

## 4. @ConfigurationProperties — 타입 안전한 설정 속성

### 핵심 개념

스프링은 외부 설정의 **묶음 정보를 객체로 변환**하는 기능을 제공한다. 이를 **타입 안전한 설정 속성(Type-safe Configuration Properties)**이라 한다.

외부 설정을 **자바 코드로 관리**할 수 있고, 설정 정보 자체도 **타입을 가지게** 된다.

### 기본 사용법 (자바빈 프로퍼티 방식)

```java
@Data  // getter, setter 포함
@ConfigurationProperties("my.datasource")
public class MyDataSourcePropertiesV1 {
    private String url;
    private String username;
    private String password;
    private Etc etc = new Etc();

    @Data
    public static class Etc {
        private int maxConnection;
        private Duration timeout;
        private List<String> options;
    }
}
```

- `@ConfigurationProperties("my.datasource")`: 외부 설정을 주입받는 객체임을 명시. KEY의 시작점 지정
- 기본 주입 방식은 **자바빈 프로퍼티 방식** → getter, setter 필요
- 스프링은 **캐밥 표기법(`max-connection`)을 카멜 표기법(`maxConnection`)으로 자동 변환**

**타입 안전이란?**
- 타입에 맞지 않는 값이 들어오면 **애플리케이션 로딩 시점에 오류 발생**
- `@ConfigurationProperties`로 만든 데이터는 **타입을 믿고 사용**할 수 있다

### 빈 등록 방법

**방법 1: 개별 등록**
```java
@EnableConfigurationProperties(MyDataSourcePropertiesV1.class)
public class MyConfig { ... }
```

**방법 2: 패키지 스캔 (권장)**
```java
@SpringBootApplication
@ConfigurationPropertiesScan  // 범위 내 @ConfigurationProperties를 자동 스캔
public class Application { ... }
```

### 문제: Setter로 인한 값 변경 가능성

자바빈 프로퍼티 방식은 setter가 있기 때문에 **실수로 값이 변경**될 수 있다. 외부 설정값은 초기에만 설정되고 이후 변경되면 안 된다.

## 5. @ConfigurationProperties 생성자 방식

**setter를 제거하고 불변성을 보장**하기 위해 생성자를 통한 주입을 사용:

```java
@Getter
@ConfigurationProperties("my.datasource")
public class MyDataSourcePropertiesV2 {
    private String url;
    private String username;
    private String password;
    private Etc etc;

    public MyDataSourcePropertiesV2(
            String url, 
            String username, 
            String password, 
            @DefaultValue Etc etc) {  // 값이 없으면 기본값
        this.url = url;
        this.username = username;
        this.password = password;
        this.etc = etc;
    }

    @Getter
    public static class Etc {
        private int maxConnection;
        private Duration timeout;
        private List<String> options;

        public Etc(
                int maxConnection, 
                Duration timeout, 
                @DefaultValue("DEFAULT") List<String> options) {
            this.maxConnection = maxConnection;
            this.timeout = timeout;
            this.options = options;
        }
    }
}
```

- 생성자를 통해 설정 정보가 **주입**됨 → setter 불필요 → **불변 객체**
- `@DefaultValue`: 해당 값을 찾을 수 없는 경우 기본값 사용
- 스프링 부트 3.0부터 **생성자가 하나**면 `@ConstructorBinding` 생략 가능 (2개 이상이면 필요)

## 6. @ConfigurationProperties 검증

타입은 맞지만 **값의 범위**가 기대와 다를 수 있다. 예를 들어 `max-connection`은 최소 1 이상이어야 한다.

### 자바 빈 검증기 (Bean Validation) 적용

```groovy
// build.gradle
implementation 'org.springframework.boot:spring-boot-starter-validation'
```

```java
@Getter
@ConfigurationProperties("my.datasource")
@Validated  // 검증 활성화
public class MyDataSourcePropertiesV3 {

    @NotEmpty
    private String url;
    @NotEmpty
    private String username;
    @NotEmpty
    private String password;
    private Etc etc;

    // 생성자 생략...

    @Getter
    public static class Etc {
        @Min(1)
        @Max(999)
        private int maxConnection;
        
        @DurationMin(seconds = 1)
        @DurationMax(seconds = 60)
        private Duration timeout;
        
        private List<String> options;
        // 생성자 생략...
    }
}
```

- `jakarta.validation.*`: 자바 표준 검증기 기능 (`@NotEmpty`, `@Min`, `@Max`)
- `org.hibernate.validator.constraints.*`: 하이버네이트 검증기 제공 (`@DurationMin`, `@DurationMax`)

> **가장 좋은 예외는 컴파일 예외이고, 그 다음은 애플리케이션 로딩 시점 예외이다.** 고객 서비스 중 발생하는 런타임 예외가 가장 나쁘다. `@ConfigurationProperties` 검증을 통해 잘못된 설정을 **로딩 시점에 발견**할 수 있다.

## 7. YAML

### YAML이란?

**YAML (YAML Ain't Markup Language)** — 사람이 읽기 좋은 계층적 데이터 구조.

```yaml
my:
  datasource:
    url: local.db.com
    username: local_user
    password: local_pw
    etc:
      max-connection: 1
      timeout: 60s
      options:
        - LOCAL
        - CACHE
```

- **공백**으로 계층 구조를 만듦
- 구분 기호로 `:`을 사용
- 스프링이 YAML의 계층 구조를 **properties처럼 평평하게 변환**하여 읽음

> `application.properties`와 `application.yml`을 동시에 사용하면 properties가 우선권을 가진다. 둘을 함께 사용하지 말 것. **실무에서는 yml을 선호**한다.

## 8. @Profile — 환경별 빈 등록

각 환경마다 **서로 다른 빈**을 등록해야 할 때 사용:

```java
@Configuration
public class PayConfig {

    @Bean
    @Profile("default")  // 기본 프로필 (로컬 개발)
    public LocalPayClient localPayClient() {
        return new LocalPayClient();  // 가짜 결제 기능
    }

    @Bean
    @Profile("prod")  // 운영 환경
    public ProdPayClient prodPayClient() {
        return new ProdPayClient();  // 실제 결제 기능
    }
}
```

### @Profile의 내부 구조

```java
@Conditional(ProfileCondition.class)
public @interface Profile {
    String[] value();
}
```

`@Profile`은 내부적으로 `@Conditional`을 사용한다! `ProfileCondition` 클래스가 현재 활성 프로필과 비교하여 true/false를 반환한다.

> `@Profile`은 결국 `@Conditional`의 특수한 형태이다. 특정 조건(프로필)에 맞는 경우에만 빈을 등록하는 것이다.
