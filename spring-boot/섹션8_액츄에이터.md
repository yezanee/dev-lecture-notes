# 섹션 8: 액츄에이터

## 1. 프로덕션 준비 기능

> "전투에서 실패한 지휘관을 용서할 수 있지만, 경계에서 실패하는 지휘관은 용서할 수 없다."

서비스를 운영하는 개발자에게 **장애는 언제든 발생할 수 있지만**, 모니터링 서비스를 구축해서 잘 대응하는 것이 중요하다.

### 프로덕션 준비 기능이란?

운영 환경에 서비스를 배포할 때 준비해야 하는 **비 기능적 요소**:

- **지표(Metric)**: 시스템 상태를 수치로 표현
- **추적(Trace)**: 요청의 흐름을 추적
- **감사(Auditing)**: 누가 어떤 작업을 했는지 기록
- **모니터링**: 전체 시스템 상태를 감시

> 애플리케이션이 살아있는지, 로그는 정상인지, 커넥션 풀은 얼마나 사용되는지 등을 지속적으로 확인해야 한다.

### 액츄에이터(Actuator)

**시스템을 움직이거나 제어하는 기계장치**라는 뜻. 스프링 부트 액츄에이터는 위의 프로덕션 준비 기능을 편리하게 사용할 수 있도록 제공하며, 마이크로미터, 프로메테우스, 그라파나 같은 모니터링 시스템과 쉽게 연동된다.

## 2. 액츄에이터 시작

### 의존성 추가

```groovy
implementation 'org.springframework.boot:spring-boot-starter-actuator'
```

### 기본 엔드포인트

`http://localhost:8080/actuator` 접근 시:

```json
{
    "_links": {
        "self": { "href": "http://localhost:8080/actuator" },
        "health": { "href": "http://localhost:8080/actuator/health" }
    }
}
```

기본적으로 `health` 엔드포인트만 노출된다. 모든 엔드포인트를 노출하려면:

```yaml
management:
  endpoints:
    web:
      exposure:
        include: "*"
```

## 3. 엔드포인트 설정

엔드포인트를 사용하려면 **2단계 설정**이 필요:

| 단계 | 설명 | 기본 상태 |
|------|------|----------|
| **1. 활성화(Enabled)** | 기능을 ON/OFF | 대부분 기본 활성화 (shutdown만 비활성화) |
| **2. 노출(Exposure)** | HTTP/JMX 중 어디에 노출할지 | 설정 필요 |

```yaml
management:
  endpoint:
    shutdown:
      enabled: true  # shutdown 엔드포인트 활성화
  endpoints:
    web:
      exposure:
        include: "*"       # 모든 엔드포인트 웹에 노출
        exclude: "env,beans"  # env, beans는 제외
    jmx:
      exposure:
        include: "health,info"
```

> **shutdown 주의!** `POST http://localhost:8080/actuator/shutdown` 호출 시 외부에서 서비스를 종료시킬 수 있다. 그래서 기본 비활성화.

## 4. 다양한 엔드포인트

| 엔드포인트 | 설명 |
|-----------|------|
| `beans` | 스프링 컨테이너에 등록된 스프링 빈 목록 |
| `conditions` | `@Conditional`의 평가 조건과 일치 여부 |
| `configprops` | `@ConfigurationProperties` 정보 |
| `env` | `Environment` 정보 (OS 환경변수, 시스템 속성 등) |
| **`health`** | 애플리케이션 헬스 상태 |
| `httpexchanges` | HTTP 호출 응답 기록 |
| `info` | 애플리케이션 정보 |
| **`loggers`** | 로거 설정 조회 및 **실시간 변경** |
| **`metrics`** | 메트릭 정보 |
| `mappings` | `@RequestMapping` 정보 |
| `threaddump` | 스레드 덤프 |
| `shutdown` | 애플리케이션 종료 (기본 비활성화) |

## 5. 헬스 정보

### 기본 조회

`GET http://localhost:8080/actuator/health`

```json
{ "status": "UP" }
```

### 상세 조회

```yaml
management:
  endpoint:
    health:
      show-details: always  # 또는 show-components: always
```

```json
{
    "status": "UP",
    "components": {
        "db": { "status": "UP" },
        "diskSpace": { "status": "UP" },
        "ping": { "status": "UP" }
    }
}
```

- **하나라도 문제가 있으면** 전체 상태가 `DOWN`이 됨
- db, mongo, redis, diskspace, ping 등 수많은 헬스 체크를 기본 제공
- 직접 커스텀 헬스 인디케이터를 구현할 수도 있음

## 6. 애플리케이션 정보 (info)

기본 제공 정보:

| 정보 | 설명 | 기본 상태 |
|------|------|----------|
| `java` | 자바 런타임 정보 | 비활성화 |
| `os` | OS 정보 | 비활성화 |
| `env` | `info.*`로 시작하는 환경 정보 | 비활성화 |
| `build` | 빌드 정보 (`META-INF/build-info.properties` 필요) | 활성화 |
| `git` | Git 정보 (`git.properties` 필요) | 활성화 |

```yaml
management:
  info:
    java:
      enabled: true
    os:
      enabled: true
    env:
      enabled: true

info:
  app:
    name: hello-actuator
    company: my-company
```

**빌드 정보 활성화:**
```groovy
// build.gradle
springBoot {
    buildInfo()
}
```

**Git 정보 활성화:**
```groovy
// build.gradle plugins
id "com.gorylenko.gradle-git-properties" version "2.4.1"
```

## 7. 로거 — 실시간 로그 레벨 변경

### 로그 레벨 조회

`GET http://localhost:8080/actuator/loggers/hello.controller`

```json
{
    "configuredLevel": "DEBUG",
    "effectiveLevel": "DEBUG"
}
```

### 실시간 로그 레벨 변경 ⭐

운영 중 긴급하게 로그 레벨을 변경해야 할 때, **서버 재시작 없이** 변경 가능!

`POST http://localhost:8080/actuator/loggers/hello.controller`

```json
{
    "configuredLevel": "TRACE"
}
```

> 운영 서버는 보통 INFO 레벨을 사용하지만, 문제 발생 시 잠시 DEBUG/TRACE로 변경하여 상세 로그를 확인하고 다시 원복할 수 있다.

## 8. HTTP 요청 응답 기록

`HttpExchangeRepository` 인터페이스의 구현체를 빈으로 등록하면 사용 가능:

```java
@Bean
public InMemoryHttpExchangeRepository httpExchangeRepository() {
    return new InMemoryHttpExchangeRepository();
}
```

`GET http://localhost:8080/actuator/httpexchanges`로 과거 HTTP 요청/응답 기록을 확인할 수 있다.

> 실제 운영에서는 핀포인트, Zipkin 등의 전문 모니터링 도구를 사용하는 것이 좋다.

## 9. 액츄에이터와 보안 ⚠️

### 보안 주의사항

액츄에이터 엔드포인트를 공개하는 것은 **보안상 위험**하다.

### 권장 방법

**1. 포트 분리 (권장):**
```yaml
management:
  server:
    port: 9292  # 액츄에이터를 별도 포트로 분리
```
→ 내부망에서만 접근 가능한 포트를 사용

**2. 인증 설정:**
- 포트 분리가 어려우면 `/actuator` 경로에 서블릿 필터, 스프링 인터셉터 또는 스프링 시큐리티를 통해 인증 추가

**3. 경로 변경:**
```yaml
management:
  endpoints:
    web:
      base-path: "/manage"  # /actuator → /manage로 변경
```
